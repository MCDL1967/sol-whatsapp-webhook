Section 1

Executive Summary

SOL Webhook currently mixes tenant/property facts across JSON packages and hard-coded runtime logic. Supabase should become the database of record for tenant identity, property data, venue catalogs, routing teams, templates, and operational events. A Menu Runtime Builder should publish a stable runtime package for the SOL Menu Runtime Service, while LOGS should read operational event tables and views.

GoalOne source of truth

Reduce duplicated config and hard-coded tenant details.

MethodSupabase schema contract

Define ownership before implementation.

RuntimePublished menu package

Menu runtime reads deterministic packages, not scattered raw tables.

ReviewCommentable artifact

Every major target can receive feedback.

Section 2

Objectives

  • Create a shared Supabase schema that both Property Admin and LOGS can trust.
  • Move tenant/property-specific facts out of runtime code and into managed configuration.
  • Preserve existing webhook behavior until schema, migration, and runtime consumption are approved.
  • Separate deployment secrets from tenant-editable settings and operational event data.
  • Give reviewers a commentable, exportable, single-page artifact for schema feedback.
  • Define the boundary between normalized Supabase data, the Menu Runtime Builder, and the SOL Menu Runtime Service.
  • Align the Tenant Property Configuration Tool with the canonical schema, including its internal and external preview responsibilities.
  • Establish a PM review workflow for comparing collaborator OKs, pending items, and notes before DB construction.
  • Separate MVP data requirements from later voice, advanced configuration, analytics, and automation scope.

Section 3

Definitions

Tenant

The client account or organization using SOL.

Property

A hotel, casino, venue, or site owned by a tenant.

Venue

A restaurant, bar, room service, entertainment location, or guest-facing service point.

Runtime Package

The stable published data shape consumed by deterministic menu runtime logic.

Template

Localized guest-facing response text with variables.

Operational Event

A logged inbound, outbound, status, reservation, complaint, or middleware event.

Hard-Code Replacement

A current literal value that should move into env, tenant config, or a published menu runtime package.

Review Target

A stable ID that comments attach to, such as table.venues.

Section 11

MVP Scope

  • MVP includes tenant, property, settings, teams, venues, aliases, templates, runtime flags, messages, reservations, and operational events.
  • MVP does not require a live property admin UI connected to Supabase.
  • MVP does not require live webhook turns to read raw normalized tables directly.
  • MVP should seed current demo data into the schema and publish a deterministic runtime package for validation.
  • MVP must preserve current webhook behavior until SOL Menu Runtime Service migration is approved.
